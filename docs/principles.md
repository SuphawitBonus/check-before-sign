# หลักการที่ห้ามละเมิด (Principles & Non-Negotiables)
โครงการ: **เช็กก่อนเซ็น (Check Before Sign)**

เอกสารนี้รวบรวมหลักการพื้นฐาน กฎเกณฑ์ความปลอดภัย และมาตรฐานทางกฎหมายที่ **ทุก Rule Pack และโค้ดทุกส่วนต้องปฏิบัติตามอย่างเคร่งครัดโดยไม่มีข้อยกเว้น**

---

## 1. ความถูกต้องและที่มาของข้อมูลกฎหมาย (Ground Truth from Official Sources)
1. **ห้ามเชื่อตัวเลขกฎหมายจากความจำหรือจากโมเดล AI (Prompt):**
   - อัตราตัวเลข มาตรา วันที่ หรือข้อกำหนดทางกฎหมายทุกข้อ **ต้องตรวจสอบและคัดลอกจากตัวบทจริงจากแหล่งทางการเท่านั้น** ได้แก่:
     - ราชกิจจานุเบกษา (สำนักเลขาธิการคณะรัฐมนตรี / `ratchakitcha.soc.go.th`)
     - เว็บไซต์ทางการของหน่วยงานผู้มีอำนาจออกกฎหมาย (เช่น สำนักงานคณะกรรมการคุ้มครองผู้บริโภค - สคบ., กระทรวงแรงงาน, ธนาคารแห่งประเทศไทย)
2. **ต้องเป็นกฎหมายฉบับที่ยังมีผลใช้บังคับอยู่ (In Force) รวมถึงฉบับแก้ไขเพิ่มเติม:**
   - ต้องตรวจสอบประวัติการแก้ไขและสถานะปัจจุบันเสมอ
3. **การบันทึกข้อมูลกำกับตัวบท:**
   - ทุก Pack ต้องจัดเก็บ Metadata ของกฎหมายให้ครบถ้วน:
     - ชื่อประกาศ / พระราชบัญญัติ
     - เล่ม ตอน หน้า และวันที่ประกาศในราชกิจจานุเบกษา
     - วันที่มีผลใช้บังคับ (Effective Date)
     - ลิงก์เอกสารต้นฉบับทางการ (PDF / URL ของรัฐ)
     - ข้อความตัวบทจริง (Verbatim Text) ของแต่ละข้อ/มาตรา
4. **หากหาตัวบททางการฉบับจริงไม่ได้:**
   - **ต้องหยุดและสอบถามมนุษย์ผู้ดูแลก่อนเสมอ ห้ามคาดเดาหรือแต่งข้อมูลขึ้นเองโดยเด็ดขาด**

---

## 2. การตัดสินผลด้วยโค้ดที่ตรวจสอบได้ (Deterministic Code, No AI Adjudication)
1. **ตัดสินด้วย Deterministic Code (TypeScript):**
   - กฎทุกข้อต้องเขียนฟังก์ชันตัดสินด้วยโค้ด TypeScript ที่มี Unit Test ครอบคลุม
   - **ห้ามส่งคำตอบให้ AI API หรือ LLM เป็นผู้ตัดสินความถูกผิดของสัญญา**
2. **ผลการตัดสินมีได้เพียง 3 สถานะ (Tri-State Evaluation):**
   - `violated` (ขัดกฎหมาย)
   - `compliant` (ไม่ขัดกฎหมาย)
   - `undetermined` (บอกไม่ได้ / ข้อมูลไม่เพียงพอ)
3. **เมื่อข้อมูลไม่พอ ต้องตอบ "บอกไม่ได้" ทันที:**
   - หากผู้ใช้เลือก "ไม่แน่ใจ" ข้ามคำถาม หรือสัญญาไม่ได้ระบุเงื่อนไขไว้ ผลลัพธ์ต้องเป็น `undetermined` **ห้ามเดาหรือสรุปผลไปเอง**

---

## 3. การตรวจสอบขอบเขตการบังคับใช้เป็นข้อแรก (Scope Gatekeeper)
1. **ข้อแรกของทุก Pack ต้องตรวจสอบว่าผู้ใช้อยู่ในขอบเขตของกฎหมายหรือไม่:**
   - ตัวอย่างเช่น ในสัญญาเช่าที่อยู่อาศัย (สคบ.):
     - ผู้เช่าต้องเป็นบุคคลธรรมดา
     - เช่าเพื่อการอยู่อาศัย (ไม่ใช่เชิงพาณิชย์)
     - ผู้ให้เช่ามีห้อง/หน่วยให้เช่าตามเกณฑ์ขั้นต่ำของกฎหมาย
     - ไม่ใช่ข้อยกเว้นตามกฎหมายอื่น (เช่น หอพักสถานศึกษาตาม พ.ร.บ. หอพัก หรือโรงแรมตาม พ.ร.บ. โรงแรม)
2. **หากไม่อยู่ในขอบเขต (Out of Scope):**
   - ระบบต้องแจ้งผู้ใช้ตรงไปตรงมาทันทีว่าไม่อยู่ในขอบเขตการคุ้มครองของประกาศ/กฎหมายนี้
   - **ต้องหยุดการตรวจและไม่ประเมินข้อที่เหลือต่อ** เพื่อไม่ให้เกิดความเข้าใจผิด

---

## 4. ข้อสงวนสิทธิ์ทางกฎหมายและช่องทางช่วยเหลือจริง (Disclaimer & Official Help Channels)
1. **ห้ามอ้างว่าเป็นคำปรึกษาทางกฎหมาย:**
   - ทุกหน้าจอแสดงผลลัพธ์และเอกสารส่งออก ต้องมีข้อความระบุอย่างชัดเจนว่า:
     > **"นี่คือการเทียบกับตัวบท ไม่ใช่คำปรึกษาทางกฎหมาย"**
2. **ต้องระบุช่องทางขอความช่วยเหลือทางการที่ยืนยันแล้ว:**
   - ต้องระบุหน่วยงานของรัฐที่รับผิดชอบเรื่องนั้น ๆ เช่น สายด่วน สคบ. 1166, ระบบร้องทุกข์ออนไลน์ `ocpb.go.th`
   - ห้ามแนะนำบริการที่ปรึกษากฎหมายเอกชนที่ไม่ได้ตรวจสอบ

---

## 5. การจัดการกฎหมายที่มีการเปลี่ยนแปลงตามกาลเวลา (Time-Sensitive Thresholds)
1. กฎหมายที่มีตัวเลขเปลี่ยนแปลงตามรอบระยะเวลา (เช่น ค่าจ้างขั้นต่ำ อัตราดอกเบี้ย เกณฑ์จำนวนหน่วย):
   - ต้องระบุวันที่ข้อมูลมีผลบังคับใช้ (Data Effective Date) ในตัว Pack
   - หน้าเว็บต้องแสดงให้ผู้ใช้เห็นชัดเจนว่า **"ข้อมูลนี้เป็นไปตามกฎหมายที่มีผลบังคับใช้ ณ วันที่ [ระบุวันที่]"**

---

## 6. ความเป็นส่วนตัวและความปลอดภัยของข้อมูล (Privacy by Design)
1. **ประมวลผลบน Client-Side 100%:**
   - คำตอบของผู้ใช้ทั้งหมดจะถูกประมวลผลภายในเว็บเบราว์เซอร์ของผู้ใช้เท่านั้น
   - **ห้ามส่งคำตอบของผู้ใช้ไปบันทึกบนเซิร์ฟเวอร์หรือลง Application Log ใด ๆ ทั้งสิ้น**
2. **การแชร์ผลลัพธ์ (Safe Sharing):**
   - ลิงก์แชร์ผลลัพธ์จะถูกสร้างขึ้นเมื่อ **ผู้ใช้กดปุ่มแชร์ด้วยตนเองเท่านั้น**
   - ข้อมูลในลิงก์แชร์จะเข้ารหัสคำตอบเชิงตรรกะผ่าน URL Hash / Query โดย **ห้ามมีชื่อ นามสกุล ที่อยู่ เบอร์โทรศัพท์ หรือข้อมูลส่วนบุคคล (PII) ใด ๆ ทั้งสิ้น**

---

## 7. จริยธรรมและข้อห้ามทางเทคนิค (Ethical & Technical Boundaries)
1. **ห้าม Scrape เว็บไซต์เอกชน:**
   - ข้อมูลกฎหมายและเกณฑ์การตรวจต้องมาจากแหล่งเปิดเผยทางการ
2. **ห้ามเลียนแบบหน่วยงานรัฐ:**
   - ห้ามใช้ตราสัญลักษณ์ (โลโก้) ชื่อหน่วยงาน หรือดีไซน์อัตลักษณ์ที่ทำให้ผู้ใช้เข้าใจผิดว่าเป็นเว็บไซต์ของหน่วยงานราชการ
3. **การควบคุมความถูกต้องของ Pack (Strict Schema Validation):**
   - ทุก Pack ต้องผ่านการตรวจสอบโครงสร้าง Schema ด้วย Zod ในกระบวนการ Build
   - หากไฟล์ `pack.json` หรือโครงสร้างไม่ตรงตาม Schema ที่กำหนด **ขั้นตอน Build ต้องล้มเหลว (Fail the Build) ทันที** เพื่อป้องกันข้อผิดพลาดขึ้น Production
